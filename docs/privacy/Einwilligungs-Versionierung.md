# Versionierung von Einwilligungen

## Regeln

- Jeder Zweck besitzt einen stabilen Schlüssel und mindestens eine unveränderliche Textversion.
- Eine Entscheidung verweist auf genau die Textversion, die angezeigt wurde, sowie Entscheider, betroffene Person, Ergebnis und Zeitpunkt.
- Redaktionelle Korrekturen ohne Bedeutungsänderung dürfen dokumentiert werden; Änderungen an Zweck, Datenart, Empfänger, Speicherdauer oder Widerrufsfolge erzeugen eine neue Version.
- Eine neue wesentliche Version setzt den technischen Zustand auf „Entscheidung erforderlich“. Alte Zustimmungen werden nicht übertragen.
- Frühere Entscheidungen werden nicht überschrieben. Die aktive Wirkung ergibt sich ausschließlich aus den jüngsten gültigen Entscheidungen für die aktuelle Version.
- Ablehnung und Widerruf sind genauso protokolliert wie Zustimmung, aber Protokolle enthalten keine unnötigen Inhalte oder Secrets.

## Ablauf bei Änderung

1. neuen Text im Vier-Augen-Prinzip anlegen und fachlich/rechtlich prüfen;
2. Version mit Veröffentlichungszeitpunkt aktivieren;
3. betroffene Funktion bis zur neuen Entscheidung sperren;
4. beim nächsten Login verständlich auf die Änderung hinweisen;
5. Zustimmung und Ablehnung gleichwertig anbieten; „später“ darf freiwillige Funktionen auslassen;
6. Ergebnis und technische Nebenwirkungen testen.
